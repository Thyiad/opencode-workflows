opencode-workflows

让 AI 无人值守地完成
「完善 plan → 实现 → 审查 → 验收 → 提交」

六个全局命令 · 零依赖 Node.js · 适用于任何接入了这套流程的仓库

开场：这是一组命令行工具，把 opencode 的 agent 编排成一条可以过夜跑完的开发流水线。一句话：你写 plan，它负责把 plan 变成经过审查和验收的提交。

为什么需要它

让 agent 写代码不难，难的是无人值守

它会说「做完了」

agent 的自述不可信：没跑通的测试、漏掉的需求，都可能被报告成通过。

它会卡住

安装挂起、测试死锁、模型不可用——没人盯着，一等就是一整夜。

它会越界

改了不该改的文档、跑了不该跑的脚本、悄悄提交或推送。

失败了没人知道

早上醒来才发现第二个里程碑就停了，后面全没动。

opencode-workflows · 02

四个痛点，后面每个设计都对应其中一个：自述不可信 → 自己重跑验收、看 git；会卡住 → 看门狗和超时；会越界 → 权限白名单和范围检查；失败没人知道 → 邮件和自动修复。

全景

从一份 plan 到一个已推送的提交

输入：初版 plan，可引用已确认的需求文档

opencode-workflows · 03

总览有两种入口：refine-and-run 先用 refine-plan 评审全部 plan 并提交，再交给 run-milestones-auto 实现。run-milestones-auto 内部调用 run-milestones，失败才尝试 Claude Code 修复。run-gated-stages 则按流水线分阶段调用 run-milestones-auto，并在配置了安全门的阶段后评审。邮件需要先配置；普通 run-milestones 不负责发邮件。

六个命令

一层包一层，各管一件事

命令做什么
refine-plan自动评审、修改一份 plan，需要你时先让 Claude 处理
run-milestones按编号跑 specs/NN-*/plan.md：实现 → 独立审查 → 自己验收 → 提交
run-milestones-auto包一层：跑完发邮件，失败时先让 Claude Code 分析修复
refine-and-run先评审并提交全部 plan，都通过后再 run-milestones-auto
run-gated-stages按流水线文件分阶段跑，阶段之间做安全评审和收尾检查
opencode-workflows-mail发一封测试邮件，确认通知配好了
refine-and-run 依次调 refine-plan 和 run-milestones-auto；run-gated-stages 调 run-milestones-auto，run-milestones-auto 调 run-milestones。每个命令都有 --help，完整行为写在 src/ 下各文件开头的注释里。npm link 一次，全局可用。

refine-plan

先把 plan 磨到能直接实现

plan-editor

DeepSeek · 负责修改

plan-reviewer

GPT · 只读评审

  • 循环到评审通过，或达到 --max-rounds 上限
  • 涉及设计决定的问题不改，标成「需人工决定」
  • 默认只改 plan.md，其他文档要用 --also 指明
  • GPT 不可用时自动换 Claude 评审

收尾检查：不信 agent 的自述

  • 改动只在允许范围内的文档
  • 每轮评审前都记录了文档版本
  • 通过的正是当前内容
  • 轮次没超限，验收命令能解析

结果写进 refine-report.md；本身不提交，由你或 refine-and-run 提交。

opencode-workflows · 05

批量模式：--only 35,36 或 --from 35 --to 37，逐个评审，每个规格独立会话，已实现的跳过，最后一封汇总邮件。需要你时怎么办见下一页。

refine-plan · 需要你时

先让 Claude 处理一轮，再来找你

能找到答案的

从代码、约定、需求文档里找到答案，直接改 plan，然后在新会话里从第 1 轮重新评审

要你决定的

不替你拍板：每个问题整理成选项和推荐，写进邮件

越界的

改了范围以外的文件，立即停下，不再评审

触发：运行失败、达到轮次上限仍有阻塞问题，或评审通过但有「需人工决定」的问题。

接手：终端里用 Remote Control 打开那个会话；做完决定后带 --accept-decisions 重跑。

退出码含义
0通过
4通过，但要你决定
3达到上限仍有阻塞
1运行失败

opencode-workflows · 06

--fix-rounds 控制 Claude 处理几轮，默认 1，0 不处理。Claude 只能改范围内的文档，重新评审时评审员也会复核 Claude 的修改。Claude 处理过时，refine-report.md 末尾多一节「无人值守 Claude 的处理」。批量时每个规格各自处理，汇总邮件列出每个要接管的会话。没装 Claude Code 也照常运行，只是不自动处理。

run-milestones

每个里程碑，同样的四步

01

实现

新的 opencode 会话里跑 /implement-plan，implementer 按 plan 写代码

02

独立审查

只读的 reviewer 对照 plan 审查，有问题就修、再审，通过才写 STATUS

03

自己验收

脚本亲自重跑 plan 里「## 验收命令」的每一行

04

提交

整个里程碑一个提交，接着下一个；任何失败都停下并提示怎么续跑

agent 只能读、改、跑白名单里的命令；提交和推送只由脚本做。中断后用 --resume 接着做，或 --review 直接进审查。

opencode-workflows · 07

规格目录 specs/NN-名字/plan.md，第一个 # 标题是名称，必须有 ## 验收命令 代码块。实现用 DeepSeek，审查用 GPT，GPT 不可用时换 Claude。也支持跨仓库占位：plan.md 里写 milestone-repo 和 milestone-spec，到这个编号时切到另一个仓库去实现。

防卡死

用超时和看门狗限制等待时间

6 h

一次 opencode 运行

--agent-timeout-hours，超时杀掉整棵进程树

45 min

一条验收命令

--command-timeout-minutes，超时即停

10 min

看门狗

10 分钟内进程树 CPU 涨不到 10 秒，判定卡死并杀掉

专治 pnpm 安装挂起、测试死锁。被杀的命令对 agent 来说就是一次失败，它得自己处理。

opencode-workflows · 08

看门狗监控 agent 启动的每个 shell 和每条验收命令，按整棵进程树（包括已退出的子进程）的 CPU 时间算。--standalone 让 OpenCode 服务和它启动的命令都留在被监控的进程树里。Ctrl+C 会停掉 opencode 和它启动的所有进程。

run-milestones-auto

失败了，先让 Claude Code 修一遍

accept

只是环境问题、文件没变：重新验收后提交

review

Claude 改了代码：清掉 STATUS，交给 reviewer 重新审查

resume

实现没做完：清掉 STATUS，继续实现

give-up

修不了：邮件写清根因和你要做什么

成功只看 git：范围内每个 STATUS 在 HEAD 里是 APPROVED，且 HEAD 已推送

没修好可接手：用 Remote Control 打开那个 Claude 会话，电脑或手机上都能继续

opencode-workflows · 09

同一套 Claude 调用和会话接管现在也用在 refine-plan 上。每个里程碑最多 --fix-rounds 轮（默认 2），后一轮续用同一个 Claude 会话。Claude 从不提交或推送；如果 Claude 那轮里工作区变了，accept 会被降级成 review，保证没有未经审查的改动进入提交。

refine-and-run

写完初版 plan，一条命令跑到底

01

评审全部 plan

选中的里程碑交给一次 refine-plan --only …，逐个评审

02

逐个提交 plan

只提交评审时的版本：docs(M35): 完善 plan：…

03

全部就绪才写代码

同样的选择跑 run-milestones-auto：实现、审查、验收、提交、推送

有 plan 需要你：其余照常评审、提交，但一行代码都不写

重跑接着做：已实现的跳过，已通过且没改过的 plan 不再评审

开始前就拒绝：在 master/main 上，或范围外有未提交改动

写代码前再查：共用文档被改、之前的通过失效时停下

opencode-workflows · 10

用法和其他命令一样：refine-and-run specs/35-foo，或 --only 35,36、--from 35 --to 37。评审全部通过时 refine-plan 不发邮件，run-milestones-auto 照常发每次结果的邮件。评审之后又改过的 plan（比如在接管会话里改的）不提交，下次重新评审。--skip-refine 跳过评审直接实现；--allow-main、--allow-dirty 放开开始前的检查。退出码：0 全部完成；plan 需要你时沿用 refine-plan 的 1/3/4；实现失败是 1。

run-gated-stages

阶段之间，以攻击者的眼光再看一遍

第 1 步

评审并修复

claude -p 按流水线的检查清单审这一阶段的 diff，修掉 high / medium 问题

第 2 步

验收后提交

脚本用这阶段的验收命令验证 Claude 的改动，再提交、推送

第 3 步

全新一轮

新的 Claude 会话、不知道之前修了什么，直到新一轮不再发现 high / medium 问题

阶段、检查清单、收尾检查都写在流水线文件里；通过的安全门按 HEAD 记住，重跑不会重复评审。

opencode-workflows · 11

每个阶段就是一次 run-milestones-auto --only 范围。最多 --gate-rounds 轮（默认 3），超过就失败，最后一个会话可以用 claude --resume 接手。阶段还可以配收尾检查：启动开发服务器，跑一个脚本，再停掉服务器。

贯穿始终的一条原则

不信 agent 怎么说，
只信脚本自己看到的

验收自己跑

agent 写了 APPROVED，脚本仍会重跑每条验收命令；plan 只提交评审过的版本

结果看 git

成功与否读 HEAD 和上游，不读 Claude 的总结

提交由脚本做

agent 和 Claude 都不提交、不推送；自动修复和安全评审不能改受保护文档
